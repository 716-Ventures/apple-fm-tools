# apple-fm-tools

Use Apple's on-device Foundation Model from Python, shell scripts, and task runners through the system `fm` command. Includes a general text/image interface and four schema-constrained advisory jobs: routing, tagging, severity scoring, and summarization.

Early development. This project was extracted from a working Paperclip integration. The repository is private while it is prepared for public use.

## Requirements

- macOS with `/usr/bin/fm` and an available system model. Tested on macOS 27 with Apple Intelligence available.
- Python 3.9 or newer. No third-party runtime dependencies.
- Apple's machine-wide CLI legal terms must be reviewed and accepted by the user. Run `sudo fm license` in Terminal if required, then `fm available`.

This project wraps Apple's installed CLI; it does not distribute Apple's model, CLI, or license. The MIT license covers this repository's code. Apple model access remains subject to Apple's terms and availability.

## Install

```sh
git clone https://github.com/chrisjdavis/apple-fm-tools.git
cd apple-fm-tools
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
apple-fm available
```

You can also run directly from the checkout with `python3 -m apple_fm_tools`.

## Generate text and inspect images

```sh
apple-fm respond 'Explain a queue in two sentences.'
printf '%s' 'Turn these notes into a short checklist.' | apple-fm respond --instructions 'Be concise.'
apple-fm respond 'Describe this image.' --image ./photo.png
apple-fm count-tokens 'Hello world' --instructions 'Answer briefly.'
```

Responses are buffered text on stdout. Errors are JSON on stderr with a nonzero exit code. `--timeout` sets the generation subprocess timeout (default 90 seconds). No shell interprets prompts. Each `respond` invocation is independent; this wrapper does not retain conversation history. For native interactive conversations, use Apple's `fm chat`.

Schema-constrained generation accepts a schema file generated by Apple:

```sh
fm schema object --name Result --string value > result-schema.json
apple-fm respond 'Set value to a short greeting.' --schema result-schema.json
```

The wrapper reads the file and passes its schema JSON to `fm`. Schema support is Apple's generation-schema format; arbitrary JSON Schema compatibility is not promised. Token counts are text-input counts, not billing, output usage, or total inference accounting.

## Validated advisory jobs

```sh
printf '%s' '{"job":"route","state":{"title":"Fix a crashing settings screen"}}' | apple-fm job
printf '%s' '{"state":"Release is blocked by final review; Alex owns the review."}' | apple-fm job --job summary
```

| Job | Validated output |
| --- | --- |
| `route` | `engineering`, `operations`, or `unknown` |
| `tag` | `bug`, `feature`, `documentation`, or `other` |
| `severity` | 0: no current impact; 1: degradation with workaround; 2: all users blocked without workaround |
| `summary` | Nonempty text, at most 70 whitespace-delimited words |

Input is a JSON object with `job` and `state`. State may be text or structured JSON. Each job returns JSON containing `provider`, `job`, `value`, `input_tokens`, and `advisory: true`. The prompt payload is capped at 2,800 tokens; this budget excludes instructions and is not a guarantee of context fit. Oversized input and invalid output fail explicitly. There is no automatic cloud fallback.

Validation checks format and allowed values. It does not establish factual correctness. Review suggestions before using them for routing or operational decisions. Treating supplied state as data in the prompt is helpful but does not guarantee prompt-injection resistance.

## Python API

```python
from apple_fm_tools import respond, count_tokens, run_job

print(respond('Explain a stack.', instructions='Use two sentences.'))
print(count_tokens('Hello world'))
result = run_job({'job': 'tag', 'state': 'Repair a broken login button'})
print(result['value'])
```

## Optional Paperclip process adapter

The jobs can read an assigned issue using the existing run environment:

```sh
apple-fm job --paperclip --job summary
apple-fm job --paperclip --job summary --publish
```

Required variables: `PAPERCLIP_API_URL`, `PAPERCLIP_API_KEY`, `PAPERCLIP_RUN_ID`, `PAPERCLIP_TASK_ID`, and `PAPERCLIP_AGENT_ID`. Keep credentials in your runtime's private environment. Without `--publish`, the adapter only reads the issue. Publishing checks out the assigned open issue and writes/verifies an advisory document with revision protection; it does not change task status or assignee. Publication is explicit and has not yet been verified through a live Paperclip process-adapter cycle.

## Development

```sh
python3 -m unittest discover -s tests -v
```

Unit tests mock `fm` and Paperclip and run without macOS or credentials. CI runs unit tests only. Live inference requires a compatible Mac and accepted Apple terms. The extracted local jobs were exercised on the development Mac; this is not a claim of broad model capability or compatibility across all Mac hardware and OS versions.

General generation, image input, schemas, and bounded jobs are the initial scope. Streaming, retained sessions, an HTTP service, and cloud inference are outside this release.
